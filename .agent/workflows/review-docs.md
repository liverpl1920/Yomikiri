# ドキュメントレビューワークフロー

## 1. ドキュメントの読み込み

- 指定されたドキュメントパスを確認し、内容を読み込む。
- 関連する他のドキュメント（PRDに対する機能設計など）も必要に応じて読み込み、整合性を確認する。

## 2. レビュー観点

以下の5つの観点で詳細に分析する：

1. **完全性**: 必要なセクションが全て含まれ、十分な情報があるか。
2. **明確性**: 曖昧な表現がなく、誰が読んでも理解できるか。
3. **一貫性**: 他のドキュメントや用語集と矛盾がないか。
4. **実装可能性**: 開発者が迷わず実装に着手できる情報が揃っているか。
5. **測定可能性**: 成功指標やパフォーマンス要件が具体的な数値で定義されているか。

## 3. レポートの作成

以下の形式でレビュー結果を報告する：

- **総合評価**: 1-5 スコア
- **良い点**: 評価できるポイント（最低3つ）
- **改善が必要な点**:
  - [必須] 重大な問題（修正案を提示）
  - [推奨] 改善推奨
  - [提案] さらなる改善
- **次のアクション**: 具体的な修正ステップ
