# プロジェクトセットアップワークフロー

## 1. インプットの確認

- `docs/ideas/` ディレクトリ内のメモや要件定義案を全て読み込む。

## 2. ドキュメントの逐次作成

以下の順序でドキュメントを作成する。各ステップでユーザーの確認と承認を得ること。

1. **プロダクト要求定義書 (PRD)**: `docs/product-requirements.md`
2. **機能設計書**: `docs/functional-design.md`
3. **アーキテクチャ設計書**: `docs/architecture.md`
4. **リポジトリ構造定義書**: `docs/repository-structure.md`
5. **開発ガイドライン**: `docs/development-guidelines.md`
6. **用語集**: `docs/glossary.md`

## 3. 作成時のルール

- 各ドキュメント作成時は、`.github/skills/` 内の対応するスキルのテンプレートとガイドを厳守する。
- 1ファイルごとに作成を報告し、「承認いただけたら次に進みます」と伝える。

## 4. 完了報告

- 全てのドキュメントが作成されたら、チェックリスト形式で完了を報告する。
