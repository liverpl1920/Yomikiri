# 実装検証ワークフロー

1. **コンテキストの理解**
   - 関連スペック (`docs/product-requirements.md`, `docs/functional-design.md`, `docs/architecture.md`, `docs/development-guidelines.md`) を読み込み、要件を完全に把握する。

2. **多角的なコード分析**
   以下の5つの観点で厳格にチェックする：
   - **スペック準拠**: 要求された機能が設計通りか、API仕様やデータモデルに相違はないか。
   - **コード品質**: 命名規則、単一責務、20-50行以内の関数長、適切なエラーハンドリング。
   - **テストカバレッジ**: ユニットテストの有無、エッジケースの網羅。
   - **セキュリティ**: 入力値検証、機密情報のハードコード禁止。
   - **パフォーマンス**: N+1問題の有無、適切なデータ構造 (Map等) の利用。

3. **自動検証ツールの実行**
   - `bundle exec rspec`
   - `bundle exec rubocop`

4. **検証レポートの作成**
   - **総合評価**: 観点別のスコア (1-5) と平均スコア。
   - **良い実装**: 具体的なポジティブフィードバック。
   - **検出された問題**: [必須] 重大な問題、[推奨] 改善、[提案] の3段階で、修正案 (Before/After) を含めて記述。
   - **スペックとの相違点**: 意図しない仕様変更がないか明示。
   - **次のステップ**: 具体的なアクションアイテム。
