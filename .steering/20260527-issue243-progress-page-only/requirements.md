# 要求内容

## 概要

積読更新画面の進捗記録方法をページ数指定入力のみに統一し、相対的に +1 / -1 する UI と関連ロジックを削除する。

## 背景

- 進捗入力方法が複数あることで、操作と仕様の理解が分かりづらい。
- ページ数指定に統一することで入力フローを単純化し、誤操作を減らす。

## 実装対象の機能

### 1. 進捗更新UIの一本化
- 書籍詳細画面の進捗更新フォームから +1 / -1 ボタンを削除する。
- ユーザーは数値入力欄への直接入力のみで進捗を記録できる。

### 2. 関連フロントロジックとテストの整理
- +1 / -1 操作に依存する Stimulus アクションと検証テストを削除または置換する。
- 既存の進捗保存（pages_read / direct_page）と表示整合性を維持する。

## 受け入れ条件

### 進捗更新UIの一本化
- [ ] 書籍詳細画面に +1 / -1 ボタンが表示されない。
- [ ] 進捗更新フォームが数値入力と更新ボタンのみで操作可能である。
- [ ] 補助文言が新仕様（ページ数指定）と矛盾しない。

### 関連フロントロジックとテストの整理
- [ ] 相対加算に依存するフロントエンド実装が残っていない。
- [ ] 進捗更新の既存機能（保存・エラー表示・ログ記録）が回帰していない。
- [ ] 既存テストまたは更新テストが新仕様を検証できる。

## 成功指標

- ユーザーが迷わず1つの入力手段で進捗更新できる。
- 進捗更新関連テストが安定して通過する。

## スコープ外

以下はこのフェーズでは実装しない:

- 進捗更新エンドポイントの仕様変更（pages_read / direct_page の受け取り方式変更）
- 読書ログ表示画面の文言変更（+Nページ表記など）
- 新しい進捗入力方式（スライダー、プリセットなど）の追加
