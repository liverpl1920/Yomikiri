# Issue #322: 【UI/UX改善】検索結果画面において、メモがヒットした場合は「本」ではなく「メモ自体」を直接表示する

## 背景

現在、統合された検索フォーム（またはメモの検索機能）においてキーワード検索を行った際、メモの内容がマッチした場合でも、結果画面には「そのメモが記載されている本」が表示される仕様になっている。
これだと、ユーザーは「本の一覧」からさらに詳細画面を開き、そこから該当するメモをスクロールして探さなければならず、目的のメモにたどり着くまでに手間がかかる。
検索の利便性を向上させるため、**メモの内容がヒットした場合は、検索結果画面に「メモ自体」を直接並べて表示する**仕様への変更を行う。

## 期待される挙動

検索結果画面（`index` ビュー）において、検索されたキーワードに応じて表示を出し分ける、あるいはエリアを分けて表示する。

- **本のタイトル・著者名がマッチした場合:**
  - 従来通り、該当する「本の一覧（カード形式など）」を表示。
- **メモの本文（content）がマッチした場合:**
  - その「メモ自体」を直接表示（どの本に紐づいているかの情報 `book.title` も合わせてラベリング）。
  - メモをクリック、または「本の該当箇所へ」というリンクから、詳細画面のそのメモの位置へダイレクトに遷移できること（アンカーリンク `book_path(book, anchor: dom_id(memo))`）。
- **本の条件とメモの条件が両方とも指定されていない（検索クリア状態、または初期状態）の場合:**
  - 本の一覧（全件）を表示。メモの一覧は非表示。
- **本の条件が指定されていないが、メモの条件（`memo_keyword`）が指定されている場合:**
  - 本の一覧は空（または非表示）になり、メモの一覧だけが表示される。
- **本の条件（`title` や `author` など）とメモの条件（`memo_keyword`）が両方とも指定されている場合:**
  - 本の一覧には、本の条件にマッチした本を表示する。
  - メモの一覧には、そのマッチした本に紐づくメモのうち、メモの条件にマッチしたメモを表示する。
