# 要求内容

## 概要

書籍登録画面で「既に読んだページ数」を任意入力できるようにし、登録直後の進捗を実態に合わせて管理できるようにする。

## 背景

現状は新規登録時の `current_page` が hidden 固定で 0 となっており、途中まで読んだ本を登録する際に進捗が実態と乖離する。

## 実装対象の機能

### 1. 書籍登録フォームの入力拡張
- 「既に読んだページ数（任意）」の数値入力欄を追加する。
- 未入力時は従来どおり `current_page = 0` として登録できるようにする。

### 2. バリデーションと進捗反映
- 入力時は `current_page` に反映し、負数不可・`target_pages` 超過不可・`total_pages` 超過不可を保証する。
- 登録後の一覧/詳細で進捗表示に反映されることを保証する。

## 受け入れ条件

### 書籍登録フォームの入力拡張
- [ ] 書籍登録画面に「既に読んだページ数（任意）」入力欄が表示される。
- [ ] 未入力で送信した場合、`current_page` は 0 として保存される。
- [ ] タイトル検索/ISBN検索による自動入力後も入力欄の値が保持される。

### バリデーションと進捗反映
- [ ] `current_page` が負数のとき保存できず、適切なエラーメッセージが表示される。
- [ ] `current_page` が `target_pages` および `total_pages` を超える値のとき保存できない。
- [ ] 正常値で登録した場合、一覧/詳細の進捗率・ページ数表示に反映される。

## 成功指標

- 既読ページ入力あり/なし双方の登録が request spec で安定して通過する。
- モデル・リクエストの異常系テストで境界値（負数/上限超過）を網羅する。

## スコープ外

以下はこのフェーズでは実装しない:

- 既存書籍の編集画面での入力UI変更
- 進捗更新（`update_progress`）API の仕様変更
- 新規カラム追加を伴うDB設計変更
