# Requirements: 月末のまとめメール（月次レポート）および年末のまとめメール（年次レポート）の送信

## 1. 概要
ユーザーが読書の振り返りを行い、モチベーションを維持するためのメール配信機能を実装します。
既存の週次・月次読書レポート配信の仕組みを拡張し、Yomikiri独自の魅力的な指標を含めた「月次レポート」の強化と、新しく「年次レポート」を追加します。

## 2. 対象機能とIssue
- **Issue #346**: 【機能追加】月末のまとめメール（月次レポート）の送信
- **Issue #347**: 【機能追加】年末のまとめメール（年次レポート）の送信

---

## 3. 詳細要件

### 3.1 月次レポート（月末のまとめメール）
- **送信日時**: 毎月1日（例: 6月分は7月1日に送信）
- **対象期間**: 配信実行日の前月1日〜前月末日（例: 7月1日実行時は6月1日〜6月30日）
- **配信内容**:
  1. **基本情報**
     - 対象期間 (例: 2026年6月1日〜2026年6月30日)
     - 宛先ユーザー名（ニックネーム。未設定時はメールアドレス）
  2. **読書実績 (インプット)**
     - 今月の総読書ページ数
     - 読書した日数 (例: 30日中 15日読書)
     - 今月読了した本一覧 (タイトル、読了日)
     - 今月読み進めた本一覧 (タイトル、今月読んだページ数)
  3. **Yomikiri独自要素 (積読解消の指標)**
     - 積読の増減 (新規登録した冊数 vs 今月読了した冊数)
     - 賞味期限 (期限) の達成状況
       - 期限内に読了できた本: ○冊
       - 期限を延長した回数: ○回 (自分への言い訳の振り返り)
       - 期限切れになっている本: ○冊
     - 来月の「賞味期限」間近な積読リスト (来月期限を迎える本の進捗と今日のノルマ)
  4. **アウトプットの振り返り**
     - 今月残したブックメモの総数: ○件
     - メモのランダムピックアップ (今月書いたメモからランダムで1〜2件抜粋して掲載)

### 3.2 年次レポート（年末のまとめメール）
- **送信日時**: 毎年1月1日（例: 2026年分は2027年1月1日に送信）
- **対象期間**: 配信実行日の前年1月1日〜前年12月31日
- **配信内容**:
  1. **基本情報**
     - 対象年 (例: 2026年)
     - 宛先ユーザー名（ニックネーム。未設定時はメールアドレス）
  2. **年間読書実績**
     - 年間の総読了冊数
     - 年間の総読書ページ数
     - 年間読書日数 (365日中 ○日)
     - 読書のピーク月 (例: 「あなたが今年最も読書に没頭したのは10月でした！」)
  3. **Yomikiri独自アワード (ランキング・ハイライト)**
     - 「電光石火アワード」(登録から最も短い期間で読了した本と、登録から読了までの日数)
     - 「最も向き合った本」(年間の読書ページ数が最も多い本)
     - 「言い訳アワード」(最も期限延長した本と、その回数)
  4. **年間のアウトプット**
     - 今年残したメモの総数: ○件
     - 特にメモが多かった本と、そのメモの抜粋 (1件)
  5. **新年に向けた「積読の現在地」**
     - 現在積まれている未読・読書中の本の総数・総ページ数
     - 新年最初の目標提案（現在積まれている本の中から期限が最も近い本を提案）

---

## 4. 実行制御・バッチ処理
- `ReadingReportDispatchJob` を拡張し、`:yearly` に対応させます。
- `reading_reports:dispatch` Rakeタスクを拡張し、以下のように起動タイミングを制御します。
  - `run_weekly = reference_date.saturday? || reference_date.sunday?` (変更なし)
  - `run_monthly = reference_date.day == 1` (翌月1日実行)
  - `run_yearly = reference_date.month == 1 && reference_date.day == 1` (翌年1月1日実行)
- Rakeタスク実行時に、各期間タイプに応じたジョブを起動します。
