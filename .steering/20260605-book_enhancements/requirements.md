# 要求内容

## 概要
書籍登録機能、表示機能、検索機能をユーザーにとってより使いやすく、また書誌情報を正確に管理できるように強化します。具体的には、複数著者の登録、翻訳者の登録、出版社の登録と検索、および「総ページ数/読了対象ページ数」の1項目への統合を行います。

## 背景
- 書籍には共著や翻訳書、出版社情報が重要であり、現状の単一著者前提や出版社未対応では正確な書誌管理ができません。
- 「総ページ数」と「読了対象ページ数」の2項目があることで、ユーザーがどちらを入力すべきか混乱し、誤入力や入力負荷が増えていました。1項目「ページ数」に統合することでこれを解消します。

## 実装対象の機能

### 1. 著者を複数名登録できるようにする (Issue #267)
- 登録/編集画面で著者を複数登録できるようにします。
- カンマ区切りの文字列として格納・表示し、入力順（並び順）を保持します。

### 2. 著者とは別に任意で翻訳者を登録できるようにする (Issue #268)
- 登録/編集画面で翻訳者を任意で入力・保存できるようにします。
- 複数翻訳者に対応するため、カンマ区切りで入力・表示できるようにします。

### 3. 総ページ数と読了対象ページ数をページ数に統合する (Issue #275)
- 「総ページ数」と「読了対象ページ数」を「ページ数」という1項目に統合します。
- 登録・編集・詳細・一覧画面および進捗計算ロジック、テスト、自動入力APIを新仕様（ページ数）に合わせます。
- 既存データ移行の際、進捗率の整合性を保つため `target_pages` の値が存在すれば優先して移行後の `pages` に代入します。

### 4. 登録時に出版社情報を追加し、出版社で検索可能にする (Issue #280)
- `books` テーブルに `publisher` カラムを追加します。
- 書籍登録/編集フォームに出版社フィールドを追加し、ISBN等の自動入力時に出版社情報が反映されるようにします。
- 検索画面および一覧画面で、出版社名による絞り込み・検索ができるようにします。

## 受け入れ条件

### 著者の複数登録
- [ ] 書籍登録・編集時に、カンマ区切り等で複数著者を登録できること。
- [ ] 登録した並び順で各画面（一覧、詳細）に表示されること。
- [ ] 既存の検索機能（著者名での絞り込み）が正常に動作すること。

### 翻訳者の登録
- [ ] 登録・編集時に翻訳者を任意で登録できること（未入力でも登録可能）。
- [ ] 登録した翻訳者が詳細画面等に正しく表示されること。

### ページ数の統合
- [ ] 「総ページ数」「読了対象ページ数」が「ページ数」1項目に統合され、登録・編集できること。
- [ ] 進捗の計算（進捗率、残ページ数、今日のノルマ）が「ページ数」を分母として正しく動作すること。
- [ ] 既存レコードのデータが適切に移行され、進捗計算の整合性が保たれていること。

### 出版社情報の追加と検索
- [ ] 書籍登録・編集時に出版社を登録できること。
- [ ] API（Google Books / openBD）からの自動入力時に出版社名が自動反映されること。
- [ ] 検索画面で出版社を指定して、その出版社名が含まれる書籍を絞り込めること。
