# 要求内容

## 概要

Issue #112 で報告された「Render 本番環境における Active Storage 設定漏れによる起動失敗」と「:local ストレージ運用によるデータ消失」を防ぐため、運用手順とマージ順序をドキュメントで明確化する。

## 背景

- Active Storage を S3 構成へ切り替えるブランチをマージする際、Render ダッシュボード側の AWS 環境変数が未設定だと本番起動失敗につながる。
- Render の無料プランではローカルファイルシステムが永続化されないため、`:local` での画像保存は再デプロイ時に消失する。
- この問題はコード修正よりも「事前チェック手順」と「マージ順序の統一」で予防する性質が強い。

## 実装対象の機能

### 1. Active Storage 本番デプロイ手順の明文化
- Render 本番へ反映する前に必要な AWS 環境変数の設定手順を明記する。
- マージ前チェックリスト（S3 バケット、Render 環境変数、確認手順）を記載する。

### 2. マージ順序の明文化
- `feature/#25-active-storage-setup` を先にマージし、その後 `feature/#26-cover-image-upload` をマージする順序を明記する。
- 順序違反時のリスク（起動失敗、画像消失）を明記する。

## 受け入れ条件

### Active Storage 本番デプロイ手順
- [ ] AWS 環境変数 4 種（`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `AWS_BUCKET`）の設定先と設定タイミングが明記されている。
- [ ] Render 側で `sync: false` が手動設定前提であることが明記されている。
- [ ] デプロイ前チェック項目が再利用可能な形で記載されている。

### マージ順序
- [ ] `feature/#25` → `feature/#26` の順序が明記されている。
- [ ] 順序が崩れた場合の具体的リスクが明記されている。
- [ ] PR レビュー時に確認できる運用ルールとして記載されている。

## 成功指標

- Issue #112 の再現条件（設定漏れ・順序違反）をドキュメントだけで回避できる。
- 新しい担当者が手順書に従って同じデプロイ判断を再現できる。

## スコープ外

以下はこのフェーズでは実装しない:

- Active Storage 実装ブランチ（`feature/#25`）のコード改修
- 書影アップロード機能（`feature/#26`）そのものの機能改修
- Render ダッシュボード値の実際の入力作業（運用者作業）
