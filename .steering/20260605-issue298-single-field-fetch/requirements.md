# 要求内容

## 概要
書籍登録・編集フォーム（`app/views/books/_form.html.erb`）において、タイトルやISBNをキーに外部API（Google Books API / openBD API）から一括で書籍情報を取得する機能に加え、特定の項目（「著者」「翻訳者」「ジャンル」「出版社」「ページ数」「書影画像」）のみを個別に外部APIから取得・補完できる「個別取得（補完）」機能を追加します。

## 背景
現在提供されている「情報取得」ボタンは一括で全項目を自動入力しますが、以下のユースケースに対応できません。
1. タイトルは手動で入力したいが、ページ数や書影画像だけを外部APIから個別に取得して補完したい。
2. 一括取得した情報のうち、一部の項目（例: 著者）だけが取得漏れしていたり誤っていたりする場合に、その項目だけを再度個別に取得し直したい（上書きしたい）。
これらのニーズに応えるため、各項目の横に個別取得ボタンを追加し、柔軟な書籍情報登録・編集体験を提供します。

## 実装対象の機能

### 1. 各フォーム項目の「個別取得」ボタン配置
- 「著者」「翻訳者」「ジャンル」「出版社」「ページ数」「書影画像」の入力項目の横に、個別に情報を取得・補完できるボタンを設置する。
- CSS (BEM) に準拠し、既存のフォームデザインに調和する形で横並びに綺麗にレイアウトする。

### 2. Stimulusコントローラーの拡張
- 「個別取得」ボタンがクリックされた際、タイトル（またはISBN）をキーに外部APIの検索を実行し、対象フィールドのみを上書き更新する。
- 検索結果をキャッシュし、同じタイトルで別の項目の個別取得ボタンが押された際はAPIを再実行せず、キャッシュから即時にデータを取得・反映する。
- ページ数の個別取得時は、取得後にノルマの再計算（`calculateQuota`）をトリガーする。
- 書影画像の個別取得時は、`cover_image_url`のhiddenフィールドを更新し、プレビュー画像を更新する。また、ファイル選択フォームをクリアする。

## 受け入れ条件

### 1. 個別取得ボタンのレイアウト
- [ ] 「著者」「翻訳者」「ジャンル」「出版社」「ページ数」「書影画像」のそれぞれの入力欄の横に、「補完」等のボタンが表示されていること。
- [ ] ボタンのデザインが既存のUIに調和していること（`btn btn--outline btn--sm`などの小型のアウトラインボタン）。

### 2. 個別取得の動作
- [ ] タイトルが未入力の状態で「個別取得」ボタンを押した場合、「タイトルを入力してください。」とステータス表示され、APIリクエストは送信されないこと。
- [ ] タイトルが入力された状態で「個別取得」ボタンを押した場合、その項目のみがAPI経由で取得した値で上書き更新されること。
- [ ] APIで値が取得できた場合、「{項目名}を取得しました。」とステータス表示されること。
- [ ] APIで値が取得できなかった（空だった）場合、「{項目名}の情報は見つかりませんでした。」とステータス表示されること。
- [ ] 同じタイトルで異なる項目の個別取得ボタンを連続して押した場合、2回目以降はAPIリクエスト（`/books/search`）が送信されず、キャッシュされたデータから即座に値が反映されること。
- [ ] ページ数の個別取得が成功した際、今日のノルマ表示が自動計算・更新されること。
- [ ] 書影画像の個別取得が成功した際、書影プレビューが表示され、ファイル選択フォームがクリアされること。

## 成功指標
- ユーザーが書籍登録・編集時に、項目ごとに必要な情報のみを外部APIから補完し、誤入力を迅速に修正・入力完了できること。

## スコープ外
- バックエンドの新しいエンドポイントの追加（既存の `/books/search` をそのまま利用するため不要）。
- タイトル自体の個別取得ボタン（タイトルは手動で入力するか、検索キーとして使われるため対象外）。
