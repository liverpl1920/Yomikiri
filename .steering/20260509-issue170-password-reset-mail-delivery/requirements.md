# 要求内容

## 概要

Issue #170 で報告された、本番環境でのパスワードリセットメール送信時エラーを解消する。SendGrid 側の一時的障害や設定不備が発生しても、ユーザー操作で 500 エラーを返さず、再試行可能な導線を維持する。

## 背景

現状は `config.action_mailer.raise_delivery_errors = true` のため、SMTP 認証失敗や接続系例外が発生すると `POST /users/password` が例外で中断し、画面遷移できない可能性がある。MVP の認証導線として、パスワード再設定フォームは障害時もユーザー体験を壊さないことが必要。

## 実装対象の機能

### 1. パスワード再設定送信時の障害耐性
- `Users::PasswordsController` で、メール送信時の SMTP/ネットワーク例外を補足する。
- 例外発生時でもフォーム再表示または適切なリダイレクトでユーザーが再操作できる状態を保つ。

### 2. 障害時のログとユーザー向け通知
- 障害原因は運用調査できるようにアプリログへ記録する。
- ユーザーには内部エラーを露出せず、汎用メッセージを表示する。

### 3. リクエストスペックによる回帰防止
- `POST /users/password` でメール送信例外が発生したケースをテストで固定化する。
- 既存の正常系（登録済み/未登録メールの同等応答）を維持する。

## 受け入れ条件

### パスワード再設定送信時の障害耐性
- [ ] `POST /users/password` で SMTP 例外が起きても 500 を返さない。
- [ ] 例外発生時にユーザーが再試行可能な画面遷移となる。

### 障害時のログとユーザー向け通知
- [ ] 障害時にログに例外クラスとメッセージが出力される。
- [ ] ユーザー表示に内部例外情報を含めない。

### リクエストスペックによる回帰防止
- [ ] 異常系スペックで例外時のレスポンス挙動を検証できる。
- [ ] 既存のパスワード再設定関連スペックが通る。

## 成功指標

- パスワード再設定リクエストでの 500 発生をアプリ側の制御で防止できる。
- Issue #170 の再現手順（フォーム送信）でエラーページ遷移が起きない。

## スコープ外

以下はこのフェーズでは実装しません:

- Render の環境変数登録や SendGrid 側ドメイン認証など、外部インフラ運用作業
- Devise メール本文テンプレートや UI デザイン変更
