# 要求内容

## 概要

積読登録画面で、過去に読んだ本（読了済みの本）も登録できるようにし、読書履歴を一元管理できるようにします。

## 背景

現状は積読前提の登録体験が中心で、すでに読了済みの本を管理対象に入れづらい課題があります。過去に読んだ本も含めてYomikiriで一元管理できることで、ユーザーの読書履歴の可視化と分析が可能になります。

## 実装対象の機能

### 1. 書籍登録フォームの拡張
- 「過去に読んだ本として登録」の選択肢を追加
- この選択肢を有効にすると、読了日を入力できるフォーム欄を表示
- 読了日は任意入力（未入力でも登録可能）

### 2. 読了登録ロジックの実装
- 「過去に読んだ本」として登録する場合、自動的に以下を設定
	- `status = completed`（読了状態）
	- `current_page = target_pages`（読み終わった状態）
	- `completed_at = 入力された読了日 or Time.current`
- 通常の積読登録（未読・読書中）フローとの互換性を維持

### 3. バリデーションの追加・更新
- 読了日が有効な日付か確認
- 読了日が未来日ではないか確認
- 不正な値に対する適切なエラーメッセージ

### 4. テストの実装
- 通常の積読登録フローのテスト
- 過去読了登録フローのテスト（読了日入力あり・なし）
- 境界値・エラーケースのテスト

## 受け入れ条件

### 書籍登録フォームの拡張
- [ ] 積読登録画面に「過去に読んだ本として登録」オプションが表示される
- [ ] このオプションを選択すると、読了日入力欄が表示される
- [ ] 読了日入力欄は任意（未入力での登録が可能）

### 読了登録ロジック
- [ ] 過去読了として登録時、`status = completed` が自動設定される
- [ ] 過去読了として登録時、`current_page = target_pages` が自動設定される
- [ ] 読了日が入力された場合、その日付で `completed_at` が保存される
- [ ] 読了日が未入力の場合、`completed_at = Time.current` で保存される
- [ ] 通常の積読登録（未読・読書中）フローに影響がない

### バリデーション
- [ ] 不正な日付フォーマットでエラーが表示される
- [ ] 未来日の入力でエラーが表示される
- [ ] その他の不正な値に対する適切なエラーメッセージ

### テスト
- [ ] request spec で通常登録フローが検証される
- [ ] request spec で過去読了登録フロー（読了日あり・なし）が検証される
- [ ] 境界値・エラーケースが検証される
- [ ] 一覧・詳細ページでの読了状態表示が正しい

## スコープ外

以下はこのフェーズでは実装しません:

- 読了日の後付け編集（読了登録後に読了日を変更する機能）
- 読了日の CSV インポート機能
- 読了期限（deadline）の自動調整
